# Audit L1 — CLOSED, and verified by the oracle it never had

**L1's claim:** the layer-window patch existed only as an **uncommitted working-tree modification** of
`vendor/llama.cpp`, so a clean checkout silently built an ABI-mismatched (stock) engine, CI never
built the real engine at all, and **every green engine-gated result was evidence about a tree no
clone reproduces**.

**The fix is a pinned fork, not a patch step.**


## The L1 guard was rewritten, because closing L1 made it vacuous

`patch_integrity.rs` asserted that every file **modified in the working tree** appeared in the patch
file. That was right while the patch *was* working-tree state. The moment the fork landed the tree
went clean, so the check found nothing to iterate, took its `modified.is_empty()` early return, and
**reported `ok` while asserting nothing** — rule 25's shape, in the L1 guard itself.

It now asserts the fork's actual invariant: **the pin is exactly one commit on top of its base, and
that commit's diff IS the committed patch** (`the_pinned_submodule_is_exactly_its_base_plus_the_committed_patch`).
That catches a second commit sneaking onto the branch, a hand-edit of the pinned tree, and the patch
file drifting from what is pinned — none of which the old form could see.

**Verified to discriminate (rule 19):** perturbing one added line in
`spike/llama-cpp-layer-window.patch` turns it red with *"the pinned submodule commit (c00bcebf…) does
not match"*; restoring it turns it green.

## What L1's closure does and does not buy

**Does:** a clean checkout builds the engine Hydra was tested with, from a SHA anyone can fetch.
Engine-gated results are now evidence about a reproducible tree. `spike/*.patch` becomes provenance.
And `vendored-gguf` becomes runnable in CI **in principle** — CI would now have to build the engine,
which is a workflow change, not a blocker.

**Does not:** remove the maintenance cost. **Every upstream sync requires re-porting the patch and
re-running this sweep before a new SHA may be pinned**, plus the positional-initializer audit. The
fork converts a *silent* liability into a *scheduled* one — and the project now owns its engine's
security updates, so an upstream CVE fix does not reach Hydra until somebody performs that sync.
