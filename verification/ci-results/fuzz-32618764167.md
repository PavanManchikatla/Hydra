## What this receipt does and does not establish

**Does:** the three parsers survived nearly two billion structure-aware hostile inputs without a
panic, an abort, or an unbounded allocation — after the two CVE-class defects the same fuzzer found
in its first second of existence were fixed (§7.28 D2, D3).

**Does not:**

* **It is not 24 CPU-hours.** It is 0.4, and the DoD stays open.
* **It is not coverage-guided fuzzing.** `hydra-fuzz` is deterministic and structure-aware; it has
  no feedback loop telling it which mutations reach new code. A libFuzzer/AFL campaign would, given
  time, reach deeper. The trade is deliberate — `(seed, iteration)` reproduction and a stable-Rust
  CI arm this project can watch run (standing rule 12) — and `cargo-fuzz` over the same entry points
  is an owed additive upgrade (§8).
* **It says nothing about the engine's own GGUF path.** `hydra-modelsvc` is the pure-Rust parser
  Hydra wrote; `llama.cpp` has its own, reached when a shard is actually loaded, and it is not
  fuzzed here.
* **Absence of a crash is not absence of a bug.** It is absence of *this* class — panics, aborts and
  unbounded allocations — under *these* generators.

## Reproducing any case

Every case is a pure function of `(target, seed, iteration)`:

```
cargo run --release -p hydra-fuzz --bin hydra-fuzz -- --target gguf --seed 1000003 --replay 412345
```

`--replay` restores the default panic hook, so the operator gets the backtrace the campaign
deliberately suppresses (one backtrace per case would be gigabytes of log and no information).
